# Gateway

The Worker (`<prefix>-gateway`) that lets an AI app, such as Claude or ChatGPT, use the dashboard's data through
MCP. It runs one OAuth server and one MCP address per module, on the dashboard's own domain. It holds no household
data: only who is connected (KV), the hashes of API keys and an audit of every call (D1).

## Addresses

| Path | What |
|---|---|
| `/household/mcp` | always there: who lives here (first names), which modules are on, where their MCPs are |
| `/<module>/mcp` | one per module that is on and built in, for example `/brain/mcp` |
| `/oauth/authorize` | the consent page. Behind Cloudflare Access, like the dashboard |
| `/oauth/token`, `/oauth/register` | the rest of the OAuth server. Called by the AI app, not by a browser |
| `/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource/<name>/mcp` | discovery |
| `/oauth/health` | which MCPs this household has |

These are Worker routes on the household's domain. They win over the dashboard's custom domain for exactly these
paths. In Cloudflare Access, every path here except `/oauth/authorize` must be let through without a sign-in
(a "bypass" rule): AI apps cannot sign in to Access, they bring a token instead, and the gateway checks it.

## How a connection is kept narrow

- **One token, one MCP.** A token names the MCP it is for. It is refused everywhere else.
- **Scopes are chosen by a person.** The consent page lists only that MCP's permissions; untick what the app should
  not do. Only people in the household config can approve, and the gateway verifies their Access sign-in itself.
- **Scopes are cut again on every call.** A tool only ever sees the scopes of its own MCP.
- **Only listed apps.** Access is only ever sent to the hosts in `src/clients.ts` (Claude, ChatGPT) or to an app on
  the same computer. To allow another app, add its host there.
- **Connections lapse** when unused for 90 days.
- **Everything is logged** in the `audit` table: who, which tool, allowed or refused. Names and ids only, never
  content.

## API keys

For the household's own programs (Alfred, a script) there are keys of the form `hmcp_<name>_…`. Only the SHA-256 of
a key is stored.

```
node scripts/new-key.mjs alfred household.read > key.sql
npx wrangler d1 execute <prefix>-gateway --remote --file key.sql
```

The key itself is printed once on the terminal's error output: store it in the password manager and as the secret
of the program that uses it (for Alfred: `ALFRED_GATEWAY_KEY`), never in the repository or a chat. To revoke one,
set its `revoked_at`.

## Files

| Path | What |
|---|---|
| `src/services.ts` | the list of MCPs and their scopes. Data only |
| `src/servers.ts` | the MCP server for each service id |
| `src/tools/household.ts` | the `household_info` tool |
| `src/oauth.ts`, `src/consent.ts`, `src/clients.ts` | the OAuth server, the consent page, the list of allowed apps |
| `src/keys.ts` | API keys |
| `src/index.ts` | the routes |
| `migrations/` | the D1 tables `api_keys` and `audit` |
| `wrangler.jsonc` | generated by `setup/wrangler-config.mjs`. Do not edit by hand |

## Adding a module's MCP

1. In `src/services.ts`, add a `ServiceDef` to `MODULE_SERVICES`: the module that switches it on, its path
   (`/<name>/mcp`), and `build(household)`, which returns its title and scopes. Scopes may depend on the people, for
   example one calendar per person.
2. In `src/servers.ts`, add its server under the same id. Each tool checks the scope it needs and writes one audit
   row through `audit()`.
3. Run `node setup/wrangler-config.mjs` so the new path gets its route.

A service without a server is not offered, and `serviceProblems` refuses a registry with clashing ids or scopes.

## Commands

| Command | What |
|---|---|
| `npm test` | unit tests (services, scopes, keys, consent page, the household tool) |
| `npm run test:e2e` | starts the Worker locally and walks through discovery, a key, the whole OAuth flow and the audit |
| `npm run dev` | `wrangler dev`. Put `DEV_PUBLIC_URL=http://localhost:8787` and `DEV_EMAIL=alex@example.com` in a git-ignored `.dev.vars` |
| `npm run typecheck` | types |
